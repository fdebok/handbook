# 工程结构与维护要求

基线记录：2026-11-27

本文记录 FDEBOK 手册当前工程形态、重构时必须保持的兼容性，以及建议的分阶段目标。它是工程整理方案，不代表目录迁移、页面重写或部署策略已经获批。任何实施都应以当前源文件和可复现的构建结果为依据。

## 目标与边界

- 提升目录职责清晰度、可维护性、测试能力和内容校验能力。
- 保持静态网站形态，不以本次整理为由引入服务端、前端框架或运行时 CDN 依赖。
- 不改变章节观点、页面文案、对外 URL、交互行为、搜索引擎语义或部署目标。
- 将 TTS 试听与模型候选作为独立工作流管理；未经单独审核，不并入网站构建或公开发布。
- 重构、提交与发布是不同的审批节点。验证通过不等于获得提交或发布授权。

## 当前架构

| 区域 | 当前职责与注意事项 |
| --- | --- |
| `src/site/pages/zh/index.html` | 中文主页面模板源文件；包含手册正文、分享数据占位符和早期主题引导脚本。构建后仍发布为 `/`。页面交互依赖稳定的 DOM 与锚点。 |
| `src/site/data/share-content.json` | 双语平台分享文案的唯一源文件；构建时注入中文与英文页面，并用于生成五个分享介绍页。 |
| `src/site/data/translations.json` | 英文文本与无障碍属性映射的唯一源文件；构建时注入两个指南页面，也供英文静态预渲染使用。 |
| `src/site/styles/site.css` | 首页样式源文件，通过首页 head 中的样式表链接加载；构建时发布到站点根目录 `/site.css`。 |
| `src/site/scripts/site.js` | 目录和页面交互脚本。通过首页底部的外部脚本加载；构建时发布到站点根目录 `/site.js`。 |
| `src/site/assets/` | 品牌图像、徽章、社交卡与二维码等网站资源源文件；构建器映射至原有根路径，保持公开 URL 不变。 |
| `src/public/` | `llms.txt`、`robots.txt`、`sitemap.xml` 与 IndexNow 验证文件的源文件；构建后仍从站点根路径提供。 |
| `scripts/build_site.py` | 从独立 JSON 源文件读取翻译与分享文案、从 `src/site/pages/zh/index.html` 读取页面模板，生成英文预渲染页及平台分享页，并将显式列出的源文件复制到构建目录。构建本身只需 Python 3。 |
| `scripts/render_brand_artwork.py` | 从未公开的设计参考生成 PNG，输出至 `src/site/assets/`；需系统级 Cairo 与 Pango。 |
| 根目录构建输入 | `LICENSE` 由构建脚本复制到输出目录；公开 URL 与源路径分开管理。 |
| `tests/` | Node.js 测试覆盖分享与颜色主题行为；Python 测试覆盖页面生成、双语元数据、分享页安全属性及音频试点结构。 |
| `.github/workflows/static.yml` | 在推送到 `main` 或手动触发后运行检查、构建并部署 GitHub Pages；工作流包含部署后的公开端点验证。 |
| `.github/workflows/validate.yml` | 对非 `main` 分支推送及面向 `main` 的 PR 运行测试和临时构建；仅有 `contents: read` 权限，不上传 Pages artifact、不执行部署。 |
| `audio/`、`services/tts/` | 当前包含双语讲稿、试听与 TTS 候选流程。试听产物和模型文件不属于公开网站内容；网站构建清单不得隐式纳入这些目录。 |
| `dist/` | 静态站点构建产物，不应手工编辑或作为权威源文件。 |

目前主页面仍是大型 HTML 文件，早期主题初始化代码仍内嵌其中；双语分享文案与英文翻译表已抽离为 JSON 源文件，并由构建器注入。后续拆分必须先定义数据归属、资源映射和渲染边界，不能仅按文件大小机械切分。

首批低风险抽取已完成：原有两段首页样式按原顺序移入 `src/site/styles/site.css`；目录初始化与主交互脚本移入 `src/site/scripts/site.js`；中文页面源文件移至 `src/site/pages/zh/index.html`。构建器仍将它们发布为 `/site.css`、`/site.js` 和 `/`。HTML 中保留早期主题引导脚本和 JSON-LD；分享文案及英译/无障碍属性映射分别由 `src/site/data/share-content.json` 和 `src/site/data/translations.json` 提供，构建时注入原有脚本节点。抽取后样式表哈希与抽取前两段样式拼接结果一致。后续仍需分模块与目录迁移，不能将这一步视为整体重构完成。

随后将 13 个正在发布的品牌与图像资源源文件移至 `src/site/assets/`，并将渲染脚本的生成目标和构建器输入映射同步调整；之后将 `llms.txt`、`robots.txt`、`sitemap.xml` 与 IndexNow 验证文件移至 `src/public/`。双语分享文案和 2,422 条英译/无障碍映射分别移入 `src/site/data/`，由构建器注入现有页面节点，浏览器无新增数据请求；构建器不再调用 Node.js 提取 JS 中的翻译。所有已发布 URL 及内容保持一致。未纳入发布清单的中文社交卡源图和批准的徽章设计参考仍作为生成输入保留。

## 必须保持的外部契约

### 路由与静态输出

构建结果必须继续包含以下页面：

- 中文主指南：`/`
- 英文预渲染指南：`/en/`
- 分享介绍页：`/share/zh/wechat/`、`/share/zh/douyin/`、`/share/en/facebook/`、`/share/en/linkedin/`、`/share/en/x/`

页面引用的章节锚点、站内链接、图片路径和其他静态资源 URL 必须保持有效。源文件可以逐步迁移，但公开输出路径不可因目录调整而变化。

### 内容、SEO 与分享安全

- 保留现有 22 章、知识域内容、附录、表格、提示、练习和双语译文；不得因抽取模板或数据而遗漏、重复或改写原意。
- 保持章节及小节锚点稳定；构建检查应能发现缺失或重复的 ID。
- 保持 canonical、hreflang、JSON-LD、标题、描述、sitemap、robots 和 IndexNow 验证文件的现有语义。
- 分享页继续使用平台专属内容、`noindex`、规范页 canonical 和限制性 CSP；不得加入脚本或嵌入内容。
- 保持品牌资源、徽章及社交预览图的文件和引用一致；未经审核不得移除历史上仍被使用的资源。

### 页面行为与体验

回归范围至少包括语言切换、目录筛选、分享平台预览与复制、设备原生分享降级、三种主题及本地保存、阅读工具/进度、自查、知识域清单和访问计数。桌面、平板与窄屏布局，键盘可用性、焦点提示、ARIA 状态和减少动态效果偏好也不得退化。

## 建议的目标目录

以下是待分阶段实施的目标草案。目录迁移前，必须先验证构建脚本能够从新源位置生成完全兼容的 `dist/`；不能把草案当作立即搬迁清单。

```text
src/
  site/
    pages/zh/                 # 中文手册页面/内容源
    data/en/                  # 英文译文数据
    data/share/               # 双语分享文案
    styles/                   # 网站样式
    scripts/                  # 页面交互脚本
    templates/                # 英文页与分享页模板
    assets/                   # 品牌和页面资源源文件
  public/                     # robots、sitemap、llms 等公开静态文件源

scripts/
  build_site.py
  render_brand_artwork.py

audio/
  scripts/
  pilot/                      # 草稿、试听和评估记录

services/
  tts/                        # 本地生成器与独立候选实现

tests/
```

章节正文是否进一步拆成单章文件，应在首轮抽取和兼容性验证之后再决定。音频稿与网站手册内容之间的关联应通过稳定章节/小节 ID 表达，不能以复制正文作为同步机制。

## 工程规则

1. **源文件唯一且明确**：文档标明每类内容的权威来源；生成页面只改源文件，不手工修补 `dist/`。
2. **构建可复现**：构建只写入指定输出目录；缺少输入、翻译或资源时明确失败，不生成看似成功的不完整站点。
3. **资源显式管理**：公开资源清单与输出路径可审计；TTS 模型、缓存、试听音频和本地环境不得被通配规则意外发布。
4. **依赖可说明**：记录构建和测试所需的 Python、Node.js 与可选工具。新增依赖须说明用途、版本策略、许可证及其是否进入用户浏览器。
5. **内容改动与结构改动分离**：结构重构不顺带改写正文、译文、品牌文案或交互细节；确需内容调整时单独列出并审核。
6. **安全默认**：不提交密钥、模型缓存或个人环境配置；分享页维持限制性 CSP；外部服务调用和新追踪行为须单独评估与批准。
7. **音频隔离**：试听服务保持本地/离线用途；未经模型与语音授权检查、用户试听验收及单独发布批准，不公开模型、试听样本或生成音频。
8. **工作区保全**：整理时先识别已有改动和未跟踪文件，不覆盖、不清理、不挪动未确认归属的工作。

## 分阶段迁移门禁

### 阶段 0：现状基线

记录工作区状态、构建和测试结果、公开路由、章节/小节 ID、静态资源清单及关键页面元数据。基线必须与已有未提交工作区分开说明。

### 阶段 1：工程说明

完善架构、测试、内容维护和发布说明；补齐项目本地环境忽略规则。此阶段不改变页面内容、构建行为或部署工作流。

### 阶段 2：低风险抽取

一次只抽取一种职责（例如样式、脚本或分享数据），保留既有 DOM、顺序、初始化时机及所有选择器依赖。每次抽取后先运行针对性测试，再运行完整回归。

### 阶段 3：构建输入与资源整理

逐步迁移翻译、模板和公开资源源文件，更新构建器与测试中的路径；验证构建输出仍包含全部既有路由和资源，且重复构建结果稳定。

### 阶段 4：体验与质量验证

在现有自动化测试之外，按基线补充页面级和浏览器级验证。覆盖常见移动端、平板和桌面尺寸，并检查键盘操作、焦点、无障碍名称、控制台错误、坏链和资源加载。

### 阶段 5：独立审核与发布

提交结构变更差异、回归结果和未解决风险供审核。提交、推送、修改部署审批机制及发布均须分别获得明确授权。

## 验收矩阵

| 类别 | 验收要求 |
| --- | --- |
| 内容 | 章节、附录、译文、表格和提示均可追溯；无意外增删、重复或空内容。 |
| DOM 与链接 | 必需的 ID 唯一且存在；内部链接目标存在；公开路径与锚点保持兼容。 |
| 构建 | 英文未翻译正文/无障碍属性检查继续有效；分享页面和静态文件（包括首页样式表和交互脚本）全部生成；构建错误明确可见。 |
| 行为 | 当前交互测试通过；核心用户流程无脚本错误；本地存储失败等现有降级行为保留。 |
| 搜索与安全 | canonical、hreflang、JSON-LD、sitemap、robots、分享页 CSP/noindex 检查通过。 |
| 响应式与无障碍 | 桌面及移动布局无溢出或遮挡；关键路径可键盘完成；ARIA、焦点和减少动态效果不退化。 |
| 性能 | 与重构前基线对比，不引入不必要的第三方请求或明显增大的首屏资源；以实际测量判断，不以代码拆分本身推断变快。 |
| 发布 | 没有明确发布批准时，不推送到会触发部署的分支，不手动触发 Pages 工作流。 |

## 常用验证命令

```sh
node tests/test_share_ui.js
node tests/test_color_theme.js
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 scripts/build_site.py --output-dir dist
```

构建命令会写入 `dist/`。验证构建时应确认输出目录目标正确；不得将源文件目录作为输出目录。上线工作流当前由 `.github/workflows/static.yml` 管理，执行本地测试不需要也不应触发部署。

阶段 0 基线检查记录：样式抽取前，两项 Node.js 测试通过；Python 测试 20 项通过；`git diff --check` 通过。源码清点到 22 个章节条目、10 个知识域条目和 6 个附录文章块。该结果是重构前的参考点，不替代后续逐内容的差异验收。
